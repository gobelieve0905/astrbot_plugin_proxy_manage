# 代理管理中心

当前版本：0.3.20

页面开发与验收遵循 [UI_CHECKLIST.md](docs/UI_CHECKLIST.md)，历史问题见 [UI_ISSUE_SUMMARY.md](docs/UI_ISSUE_SUMMARY.md)。后续 UI 优化不得绕过页面生命周期、脱敏和真实状态契约。

## 产品方向

本插件的最终目标是成为 AstrBot 的统一出站流量控制面：由插件自行准备和管理可插拔代理内核，管理机器人平台、模型 Provider、Agent 工具、插件、下载及相关服务产生的实际外部流量，而不是只维护订阅和节点列表。

Mihomo 只是候选内核之一，架构不得与任何单一内核绑定。完整的产品不变量、内核适配器契约、流量范围、安全模型和验收标准见[《最终产品定义与架构约束》](https://github.com/gobelieve0905/astrbot_plugin_proxy_manage/blob/develop/docs/PRODUCT_DEFINITION.md)。该文档是后续设计和修改的最高优先级依据。

> 当前 0.3.20 延续版本化官方兼容层。AstrBot 4.28.1 的飞书和 Telegram 平台，以及首批 Provider 由插件在运行时注册显式代理兼容类；第三方插件和 MCP 仍通过公开声明接入。未知 AstrBot/SDK 版本不会乐观启用兼容层。默认未命中规则由内核执行 `DIRECT`，但只有请求级证据才能显示“已接管”。

首次安装、AstrBot 接入范围、协议与部署支持矩阵见 [USER_GUIDE.md](USER_GUIDE.md)。

内核状态会明确显示为：未配置、连接失败、认证失败、版本不支持、已连接、配置未应用或运行配置不一致。原生协议节点在内核未就绪时显示“待接入内核”，测速任务显示“未执行”；这类状态不会计入节点失败数。

页面中的 `[configured]` 表示已配置且保持原值；留空表示清空，输入新值表示替换。节点连接参数、订阅令牌、控制密钥和带认证代理入口不会通过页面状态、事件或错误信息返回。

内核管理页面第一栏是“运行控制”，第二栏是“内核资源管理”。资源管理以三条可独立收放的横栏列出 Xray、Mihomo、sing-box，版本选择、在线操作、校验信息和离线安装均归入对应内核；插件安装后不会自动下载内核，用户下载并校验后再启用。运行控制只允许切换、启动已下载且已启用的内核，同一稳定入口同时只运行一个主内核。更新失败会恢复上一份可运行制品。Xray 的代理组切换和运行连接明细能力有限，页面会明确显示，不伪装成其他内核的 HTTP 控制面。

操作结果使用自动消失的短时通知，不长期占用页面空间。顶部“预览并保存”会按订阅、节点、代理组、规则和平台分区展示本轮新增、删除和修改摘要，不显示原始配置 JSON、完整订阅地址或连接凭据。代理组配置和运行状态集中位于“代理组”页面，与内核资源管理分离；每个代理组以可收缩项一一对应展示配置摘要和运行状态，展开后查看成员、编辑、切换和逐组测速。进入该页面或手动刷新后读取当前内核的实际选择。代理组配置采用独立可视化弹窗，代理组名称必须唯一，直连只作为内核内部目标保留，不作为可编辑代理组；新增或编辑组时使用点击切换的节点选择器，每个节点同时显示所属订阅、协议和地区，支持关键词筛选以及对当前筛选结果全选/全不选。手动模式可指定初始节点；`url-test` 按有效测速结果选择延迟最低节点，`fallback` 按成员顺序故障切换。

代理组状态支持逐组核对，使用当前代理组配置的测速目标；对 `url-test` 会读取组内成员的测速结果，分别显示当前实际选择、最低延迟、切换容差和成员明细，从而判断当前节点是否符合“最低延迟 + 容差”策略。核对记录保存在插件私有状态中，不进入流量策略；测速目标或组成员修改后会标记为过期。Mihomo 和 sing-box 支持组核对；Xray 不提供组控制接口，且共享只读内核不会执行主动核对。

节点管理页主列表收敛为名称、协议/支持状态、地区、健康状态、延迟和常用操作；连接入口、执行内核、订阅来源、代理组归属、排除测速设置及诊断信息通过“详情”二级弹窗查看或编辑。主列表仍显示最近一次成功测速的延迟；勾选节点后可只测速所选节点，全选与全不选仅作用于当前筛选结果，筛选切换不会清除其他筛选结果中已选节点。全部节点测速仍可单独发起。

跨容器入口不得发布为宿主机或公网端口。stdio MCP 通过子进程环境使用回环入口；独立 MCP 容器必须加入明确受信的容器网络并使用认证入口；同机独立进程在没有受控宿主机回环转发时保持“未接入”。加入同一容器网络的服务具备网络层可达性，因此仍须保留代理认证这一层防护。

内核资源卡片内执行安装、覆盖安装、更新和卸载，并展示任务阶段与进度；运行中的当前内核不能卸载，停止状态卸载会同步取消启用。每个受信来源都有连接、无数据和总时限；全部来源失败后页面进入“等待离线上传”，显示可复制的明文官方下载地址、固定文件名和 SHA-256。离线上传与在线下载使用同一固定摘要，下载失败不会覆盖已安装内核。当前固定清单只启用 GitHub 官方源，尚未加入未经验证的第三方镜像。

管理页使用固定桌面侧栏和移动端横向导航，订阅、节点、代理组、规则、平台、内核及日志分别使用与数据密度匹配的布局。长订阅地址、节点 URI、制品摘要和错误信息允许换行或滚动，不会挤压相邻操作；浅色、深色和窄屏状态使用同一语义色体系。

专用实例应用按“生成候选、校验、备份、应用、完整核对”执行。节点类型、代理组类型和成员、当前选择、规则内容与顺序必须全部一致才会标记为已应用。失败时只会恢复修订标识一致的上一份已验证配置；若不存在已验证配置，则写入并核对 `MATCH,REJECT` 失败关闭配置，禁止自动回落到直连。恢复失败会显示独立故障状态。

实际出站验证分别报告“入口请求、运行规则、出口证据”。入口请求成功不等于出口已确认；只有同一次请求能够关联到内核连接记录，记录中的规则、代理组和实际节点链路与预期一致，并取得有效出口 IP 时，才标记为“出口已确认”，否则显示“无法判定”。

当前已验证支持 AnyTLS、HTTP、HTTPS、SOCKS5/SOCKS5H 的 URI，以及 Clash YAML 中的 AnyTLS、HTTP（含 TLS）和 SOCKS5。Xray 适配器已加入独立制品、配置边界和进程运行生命周期；VMess、VLESS、Trojan、Shadowsocks 等协议仍会按统一模型标记为“未验证”，完成真实运行验证前不会写入配置。Xray 不支持的自动测速组、回退组和运行时控制会明确标记。其他可识别协议会完整保留，未知协议标记“不支持”，不会静默丢弃。疑似流量、重置或到期提示的条目只显示提醒，必须由用户确认后才排除测速和组选优。

AstrBot 核心接入会先备份原有 `http_proxy` 和 `no_proxy`，写入稳定入口后要求重启 AstrBot。`no_proxy` 只保留回环，以及从当前 MCP 配置安全识别出的私网、`.local` 或容器服务名；新增内部 MCP 后会提示重新接入和重启。外部域名的直连由内核 `DIRECT` 规则决定。插件停用或热重载时不会自动恢复旧配置；这保证自管内核停止后请求失败，而不是静默回落到直连。

订阅可设为自动更新或 `0` 分钟的纯手动更新；每个订阅必须有唯一的自定义名称。导入页面提供“导入订阅”和“批量导入”两个入口：单条入口一次只接受一个链接，批量入口在独立弹窗中按“名称 | 链接”逐条预览。预览会展示来源、节点数量、协议、地区、订阅流量/到期信息和节点清单，但不会显示完整认证参数；确认导入后会自动发起一次节点测速，状态以不会占用页面的自动消失横幅反馈。每次刷新展示新增、变更、删除和未变节点；用户别名、排除状态和代理组成员引用会保留，刷新时已删除节点以失效引用继续显示。手动删除订阅节点会记录在订阅的忽略列表中，后续刷新和保存不会重新导入；如需恢复，可显式重新导入同一订阅。删除订阅时会级联删除其名下节点、健康记录和代理组引用，避免已删除来源的节点继续测速或进入运行配置。刷新或导入失败时继续使用上次有效配置。

为 AstrBot 提供通用的代理出口、分流规则、节点状态和连通性诊断能力。

本版本不实现系统级 TUN、透明代理或 DNS 接管，也不开放任意 URL 代理转发。订阅、测速和出口验证地址会拒绝回环、私网、链路本地、保留地址、云元数据目标及危险重定向。插件自管内核不等于 AstrBot 所有流量已自动接入；平台、Provider、Agent 工具、其他插件和 MCP 仍须按动态流量接入清单逐项实现和验证。

## 实际流量接入

插件通过当前适配器为每个已验证节点生成独立出站，并用稳定唯一的内核名称生成代理组和规则。页面继续显示用户名称，同名节点仍能分别测速和切换；代理组只包含用户明确选择且当前可用的节点。Mihomo 使用 YAML 与 Meta 控制接口，sing-box 使用原生 JSON 与 Clash API 兼容控制面，Xray 使用原生 JSON 和进程级健康检查，专用结构均留在各自适配器内。未验证协议会保留原始信息，但在完成适配前不会写入运行配置。控制端口和统一入口仅绑定插件运行环境内的回环地址并启用随机密钥认证。
