# 代理管理中心

当前版本：0.2.10

内核状态会明确显示为：未配置、连接失败、认证失败、版本不支持、已连接、配置未应用或运行配置不一致。原生协议节点在内核未就绪时显示“待接入内核”，测速任务显示“未执行”；这类状态不会计入节点失败数。

页面中的 `[configured]` 表示已配置且保持原值；留空表示清空，输入新值表示替换。节点连接参数、订阅令牌、控制密钥和带认证代理入口不会通过页面状态、事件或错误信息返回。

当前已验证支持 AnyTLS、HTTP、HTTPS、SOCKS5/SOCKS5H 的 URI，以及 Clash YAML 中的 AnyTLS、HTTP（含 TLS）和 SOCKS5。其他可识别协议会完整保留并标记“未验证”，未知协议标记“不支持”，不会静默丢弃。疑似流量、重置或到期提示的条目只显示提醒，必须由用户确认后才排除测速和组选优。

为 AstrBot 提供通用的代理出口、分流规则、节点状态和连通性诊断能力。

插件页面位于 AstrBot 插件详情中的「页面」。配置保存为插件数据目录内的 JSON 文件。生产环境建议为 Telegram、Meta、GitHub 分别建立独立策略，并启用失败关闭，避免代理失败时自动回退直连。

本版本不实现系统级 TUN、透明代理或 DNS 接管，也不开放任意 URL 代理转发。订阅导入只解析节点元数据；Mihomo / Clash 外部控制接口默认关闭，需要用户显式配置地址和密钥。后续版本将继续完善节点测速、配置导入导出和历史版本管理。

## 实际流量接入

插件通过 Mihomo 的 `proxy-providers`、`proxy-groups` 和 `rules` 生成运行配置。订阅中的 AnyTLS、VMess、VLESS、Trojan、Hysteria2 等原生协议由 Mihomo 内核解析，插件不把它们伪装成 HTTP 节点。控制接口地址、端口和密钥与实际代理入口分开配置；控制接口用于管理和核对内核，代理入口用于 AstrBot 出站。启用控制接口后，可通过运行配置接口预览并应用配置。插件默认只管理订阅、代理组和规则范围，不接管现有内核的完整 DNS、监听和其他全局配置；不会假设固定容器名、服务器 IP 或生产路径。
