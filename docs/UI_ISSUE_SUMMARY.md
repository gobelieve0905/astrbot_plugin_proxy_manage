# UI 问题复盘与防范

## 已知故障模式

### 页面完全空白

常见原因是重建 HTML 时误删 `body`、主容器或关键按钮，脚本随后对不存在的元素调用 `addEventListener`。修复时保留完整 HTML 结构，并用静态 id 清单检查。

### 首屏脚本报 `AstrBotPluginPage` 未定义

AstrBot 会在页面脚本之后注入 bridge。脚本顶层读取 bridge 或使用过早的 ES module 会在注入前失败。当前规范要求普通脚本、`DOMContentLoaded` 初始化和 `await bridge.ready()`。

### 渲染后按钮失效

`innerHTML` 会销毁旧节点和监听器。所有动态节点必须集中在 `bind()` 中重新绑定；全局按钮放在 `#content` 外，避免被重绘删除。

### 优化后状态被误报成功

前端不能把接口返回、配置生成或控制 API 存活当成真实流量接管。页面必须沿用后端的入口、规则、出口三段证据，并显示“无法判定”。

## 改版流程

1. 先复制当前页面并只做一个小改动。
2. 运行静态检查，确认关键 DOM、脚本加载方式和桥接初始化契约未变。
3. 用 bridge mock 检查无脚本异常，再检查桌面/窄屏布局。
4. 只在本地静态检查通过后提交；AstrBot 加载、重载、回滚和真实出口验证在服务器执行。
5. 记录变更日期、影响页面、已知限制和服务器验收结果。

不要通过内联一大段自动生成 HTML、删除旧结构或引入未锁定的 CDN 来“快速修复”页面。
