# 删除资源时的出口策略保护

日期：2026-10-09；修复归属：0.4.4。

## 范围与失败语义

- 保护进入 AstrBot 统一代理入口、命中原代理规则的请求，避免删除最后一个节点或订阅后，规则消失而落入默认 DIRECT。本轮不新增流量接入点，也不宣称新增真实出口验证。
- 规范化模型只清理已删除节点的成员引用和当前选择，保留空代理组及原规则目标；主动删除代理组仍保留规则的失效目标。草稿可保存、重载和修复。
- 统一模型检查空组及启用规则的缺失/停用目标；Mihomo、sing-box、Xray 在生成候选配置前共同检查。内核专用配置转换仍留在适配器内部。
- 应用在查询内核、写配置和修改运行证据之前拒绝失效草稿；上次运行配置不变。保存草稿标记待应用，保留上次已应用文档与修订。重启继续采用既有可信恢复流程；无可信基线时使用失败关闭配置。
- 已有效应用的规则和默认出口不变；补充节点或明确改选新出口后才允许应用。真实请求是否经过预期出口仍须由既有请求、命中规则、链路及出口证据确认，配置生成或本轮健康检查不能替代此证据。

## 页面状态与文档

- 节点/订阅删除后的空组显示“空组 · 待处理”，保留规则并引导补充节点或处理分流规则。
- 代理组删除后的目标下拉框保留“目标已失效”，不默认显示 DIRECT；保存差异说明可保存但不能应用。
- 应用失败沿用错误提示；修复后警告消失。布局、键盘和屏幕阅读器仍需服务器浏览器验收；本轮不在本机运行页面。
- README、USER_GUIDE、CHANGELOG 同步描述草稿和应用限制，未扩大已接管能力声明。开发文档由现有 `/docs export-ignore` 排除安装包。

## 自动化与验收

- 本机仅执行 Python AST、JavaScript 语法和 Git 差异检查，不执行插件或运行测试。
- 服务器使用既有 AstrBot 镜像、无网络隔离检查容器运行 162 项回归，全部通过；不启动第二个 AstrBot 或平台连接，不发送测试消息。
- 回归覆盖：删除订阅和最后一个节点、成员引用清理、原规则匹配保留、保存/重载、旧/新规则缺失目标、三种内核一致拒绝、显式修复后生成、应用拒绝前无配置写入或运行证据替换。
- 固定提交部署通过既有备份、部署锁与回滚入口执行；部署后核对已安装文件摘要、插件加载、服务健康和当前内核状态。具体提交、检查数量和结果由部署归档保存。
