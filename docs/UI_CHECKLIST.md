# 代理管理中心 UI 开发与验收规范

版本：1.0 · 最后更新：2026-09-21

这份规范用于后续 UI 优化。页面必须先保持可加载、可操作和可恢复，再进行视觉调整。

## 1. 页面生命周期

- `index.html` 必须保留完整的 `html/head/body` 结构、主导航、`#content`、通知区和配置确认对话框。
- 页面脚本必须使用普通脚本加载；初始化放在 `DOMContentLoaded` 中，并等待 `window.AstrBotPluginPage.ready()` 后再调用接口。
- 页面桥接对象不可在脚本顶层直接解引用。桥接缺失时显示可见错误，而不是让页面静默空白。
- `render()` 只能替换 `#content` 的内容；全局按钮和通知节点必须位于内容区之外。
- 每次渲染后重新绑定动态控件；重复绑定必须可安全执行，不得叠加定时器或事件。

## 2. 结构与资源

- CSS、JavaScript 和 HTML 使用相对路径，文件名大小写必须与仓库一致；不依赖构建步骤、CDN 或模块解析。
- 页面功能所需的 DOM id 只能删除或改名时同步修改脚本和静态检查。
- 备份文件、临时脚本和未使用资源不得进入插件归档。
- 所有异步请求显示加载、成功、失败三种状态；错误必须进入 `#notice`，且不会覆盖当前可用数据。

## 3. 数据与安全

- 页面只展示脱敏快照；订阅令牌、节点凭据、控制密钥和认证代理 URL 不得进入 DOM、事件或错误文本。
- 仅把后端返回的真实状态显示为“已接管/已验证”；配置生成、控制 API 可达或节点列表存在不能替代实际流量证据。
- 破坏性操作（删除、卸载、回滚、切换运行内核）必须确认，并在失败时保留当前页面状态。
- 保存流程必须是预览差异 → 用户确认 → 后端校验/备份/原子写入/应用；前端不得自行宣称已应用。

## 4. 响应式和可访问性

- 桌面使用固定侧栏和可滚动内容；窄屏切换为横向导航，不能隐藏唯一操作入口。
- 长 URL、错误、摘要和 JSON 使用换行或滚动，不得撑破布局。
- 导航按钮使用 `aria-current`，输入控件有可见标签，通知使用 `role="status"` 或等价语义。
- 颜色只表达状态，不能作为唯一信息；焦点状态、禁用状态和错误状态必须可辨识。

## 5. 最小验收清单

1. 静态检查 HTML 中存在主导航、`#content`、`#notice`、`#reload`、`#save`、`#rollback`、`#diff`。
2. 静态检查 `app.js` 不在顶层读取 `window.AstrBotPluginPage` 的成员，不使用 `type="module"`。
3. 使用 bridge mock 打开页面时无 `pageerror`，首次加载能请求 `state` 和 `kernel-status`。
4. 点击每个导航后内容仍可见，刷新、保存、取消、回滚失败时页面不消失。
5. 在桌面、700px 以下窄屏和深浅主题下检查无横向溢出、重叠或不可见文字。
6. 服务器 AstrBot 环境完成真实加载、接口调用、插件重载和回滚验收后，才可宣称 UI 修复完成。

后续视觉改版必须逐项保留以上契约；只改颜色、间距、排版时也要重新执行最小验收清单。
