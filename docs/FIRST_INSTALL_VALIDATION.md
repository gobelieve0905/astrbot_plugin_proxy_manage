# 首次安装引导与受限下载验收

日期：2026-10-09

## 本轮范围

- 改善固定内核制品下载：没有已校验自管内核时，避免下载依赖尚未运行的稳定代理入口。
- 规范化业务模型和三个内核适配器不变；新增只读 `kernel_setup` 快照及显式安装请求的 `bootstrap` 选择，下载器负责通道和重定向限制。内核专用制品仍由适配器提供。
- 初始化、状态接口和页面显示平台、资源、启用、启动的真实状态；不信任外部预装内核，不自动下载，不把安装或入口配置视为业务已接管。
- 受限引导是用户主动选择的固定制品供应链通道，实际业务出口仍须原有请求级入口、规则、链路及出口证据。流量清单明确区分引导直连与稳定入口下载。

## 失败、持久化与回滚

- 引导客户端关闭环境代理继承；不更改 AstrBot 的持久代理、进程环境、NO_PROXY、业务策略或已应用配置。
- 已有已校验或运行中的内核时，后端拒绝引导直连；下载通过显式稳定入口，入口故障不回退直连。每次尝试/重定向重新核对首次安装资格。
- HTTPS、受信目标、逐跳公网校验、重定向上限、600 秒总超时、60 秒空闲超时、64 MiB 归档上限及固定 SHA-256 保留；摘要不符不会替换现有制品。
- 原有原子安装记录、上一份制品、启动/应用失败恢复流程继续使用；无可信运行配置时内核保持失败关闭。新安装资源仍需用户启用、启动并应用策略。
- README、USER_GUIDE、CHANGELOG 与产品定义同步说明受限引导例外；开发验收文档沿用 `/docs export-ignore`，不进入运行 ZIP。

## 验证记录

- 本机只做 Python AST、JavaScript 语法、Git 差异静态检查，均通过；未在本机执行插件。
- 服务器使用既有 AstrBot 镜像，在无网络隔离检查容器运行 158 项回归，全部通过；没有启动第二个 AstrBot 或飞书连接。
- 新增回归覆盖：空安装目录检测、启用/启动状态、显式引导选择、已有内核拒绝直连、环境变量不变、GitHub 官方分发重定向、第三方/HTTP/内网/非标准端口/认证 URL 拒绝，以及代理入口失败无直连回退。既有摘要、回滚、订阅失败关闭和兼容层检查继续通过。
- 浏览器布局、键盘与屏幕阅读器验收暂未执行：服务器未安装浏览器自动化运行环境，本轮没有在本机运行页面测试。服务端接口和真实下载结果在部署收尾记录中报告。
