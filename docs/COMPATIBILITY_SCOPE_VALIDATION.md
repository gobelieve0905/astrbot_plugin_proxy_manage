# 官方兼容层检查范围隔离

日期：2026-10-09；修复归属：0.4.4。

## 本轮范围

- 改善 AstrBot 官方平台和 Provider 的稳定代理入口安装：无关 SDK 缺失或变化不再阻断这些路径。
- 规范化策略、内核适配器和代理入口不变。仅调整版本检查、组件安装/重载范围和流量清单诊断，不引入内核专用假设。
- AstrBot 核心版本仍是公共前置条件；Lark 依赖 lark-oapi、websockets，Telegram 依赖 python-telegram-bot，Provider 使用自身依赖声明和既有方法指纹。未审计类型仍保留原类。
- 安装成功与真实流量验证继续分开。测试中的代理参数证明适配行为，不证明新的公网请求经过预期出口；实际出口仍需同次请求的入口、规则、连接链路与出口证据。

## 失败、持久化和回滚

- 不匹配组件不导入或替换目标类，并报告实际/所需依赖版本；安装或模块异常只记录该组件，不撤销其他成功适配。
- Lark SDK hook 安装中途失败会恢复其原始 hook。重载异常或超时保留已安装适配和覆盖信息，单独报告需要检查/重启，未安装的平台不会重载。
- 注册表与 SDK hook 的修改仅在进程内；插件策略、已应用配置、环境代理和持久化格式不变。恢复操作仍还原已替换的注册类及 Lark hook，部署采用既有备份、锁与回滚流程。
- 对未适配客户端不能保证强制失败关闭，不新增直连回退，也不宣称未经验证的路径已接管；服务器既有稳定入口与内核失败关闭配置保持原状。

- 本机仅做 Python AST 和 Git 差异静态检查，不运行插件或测试。
