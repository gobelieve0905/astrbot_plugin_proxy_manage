# 组件流量策略服务器验证

日期：2026-10-08

版本：0.4.2 develop，Unreleased 功能

## 范围

本轮改善声明兼容的 AstrBot 市场插件、stdio MCP 和私网 MCP 的来源路由。持久化增加内核无关 `component_routes`；三个内核适配器各自生成专用 HTTP 入站与优先来源规则；市场插件公开 lease 返回对应入口；用户显式操作可备份并原子保存 stdio MCP 代理环境。

本机只编辑与静态核对；回归和原生内核探针在服务器、现有 AstrBot 镜像的隔离网络环境运行，无生产飞书连接、业务凭据或测试消息。曾误调用一次本地 unittest，因缺少 httpx 在导入阶段失败，未启动 AstrBot；该输出不作为验收证据。

## 结果

- 服务器候选源码全部 152 项 unittest 通过，包含 8 项新组件回归；源码暂存目录 `/var/tmp/proxy-manager-components.Vxgg7j`。
- Mihomo：真实 HTTP 请求分别通过插件 A、MCP B 与 DIRECT 专用入口，响应包含预期出口标记；命中所有测试目标的普通域名规则不能覆盖组件规则。运行控制接口的完整规则核对通过。
- sing-box：相同真实 HTTP 请求验证不同组、DIRECT 与来源优先级；停用组件入口拒绝请求，重启后仍拒绝，其他组件继续正常。
- 两种已安装内核：私网组件无认证请求被拒绝，有测试认证的请求经指定出口返回；整个探针只使用固定测试凭据。
- Xray：适配器结构、入口端口、来源规则和凭据脱敏回归通过；服务器未安装其原生核心，未执行真实请求探针。
- 市场插件 lease 回归覆盖有效专用入口、停用拒绝、陈旧修订拒绝和旧公共入口兼容。
- stdio MCP 显式接入回归覆盖代理环境修改、原配置备份、其他服务器/业务参数保留与响应脱敏。

## 失败与限制

停用、删除策略和失效代理组保留稳定拒绝入口，不复用旧组件端口，不静默切到 DIRECT。保存/应用沿用现有配置事务和回滚；只保存时运行策略不改变，应用失败恢复上一份已验证配置或失败关闭配置。MCP 配置先写私有备份再原子替换，并检查文件是否被并发操作修改。

来源路由依赖组件确实使用专用入口。只读全局环境的旧插件仍使用公共入口，远端进程/容器不会被自动修改；MCP 保存环境后必须重启进程。已有长连接需由组件关闭或重建。TCP/UDP、manual、同机独立进程和外部 MCP 显示需适配。HTTP 探针不代表 HTTPS、WebSocket 或第三方业务 SDK 已完成逐项验收。

服务器当前 MCP 清单为空，生产组件的请求级验收仍需其作者按协议接入后执行；“策略已应用 · 未验证”只表示配置修订应用，不标成已接管。服务器无浏览器运行时，本轮 UI 完成 JS 语法与静态布局检查，未完成截图验收。
